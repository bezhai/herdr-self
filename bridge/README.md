# Herdr Bridge

连接本机或 SSH 上的 Herdr，把飞书聊天路由到 Herdr 中的 Agent：每个飞书话题对应 Herdr 里一个 tab 中的 Agent 会话。网页提供机器、飞书应用、会话绑定和话题管理。

## 启动

需要 Node.js 24+。运行 Agent 的机器需要安装 Herdr，以及绑定所选 Agent 的命令行工具（Claude Code、Codex 或 Antigravity CLI `agy`）。

Bridge（SSH 连接时为 SSH 登录用户）必须与 Herdr server 使用同一用户和相同的 `HOME`、`XDG_CONFIG_HOME`：`herdr --session <name>` 按 `$XDG_CONFIG_HOME/herdr/sessions/<name>/herdr.sock` 查找 server，未设置 `XDG_CONFIG_HOME` 时使用 `$HOME/.config/herdr/sessions/<name>/herdr.sock`。

```bash
cd bridge
npm ci
npm start
```

`npm start` 先用 Vite 构建管理台（输出到 `web/dist/`），构建失败则不会启动。只支持安装完整依赖的源码部署：使用 `npm ci`，不要加 `--omit=dev`，构建工具在开发依赖中。Bridge 目录需要可写。前端未构建时 `/` 与 `/connect` 返回 503。

打开 `http://localhost:8080`。首次启动生成 `state/access-key`，使用该文件中的访问密钥登录。状态目录包含应用凭证和会话配置，不应提交到 Git。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PORT` | `8080` | HTTP 端口 |
| `BIND` | `0.0.0.0` | 监听地址 |
| `BRIDGE_HOSTS` | 空 | 允许访问的额外域名或 IP，逗号分隔，不含端口 |
| `BRIDGE_STATE` | `bridge/state` | 状态目录 |
| `BRIDGE_URL` | 空 | 管理台对外地址，例如 `http://host:8080`，用于机器人在飞书里回复的绑定链接。只能是 http(s) 地址，不带路径、查询参数和 `#`，末尾的 `/` 会去掉；格式不对时 Bridge 不会启动。未配置时机器人只提示到管理台完成绑定 |

默认允许 localhost、127.0.0.1 和当前主机名。通过其他地址访问时配置 `BRIDGE_HOSTS`；`BRIDGE_URL` 中的主机名也需要在允许范围内。当前管理台采用单用户密钥登录；公网部署需要 HTTPS 反向代理。

## 接入

1. **机器连接**：添加本机或 SSH 连接，选择 Herdr session。SSH 使用 Bridge 主机的配置、密钥和 known_hosts。
2. **平台连接**：点击添加飞书，在官方页面新建或选择已有应用。确认后自动保存凭证并建立长连接。新应用创建者自动加入允许名单；也支持手动填写已有应用凭证。连接成功和验证凭证后，应用名称和头像以飞书机器人为准。
3. **会话绑定**：在飞书里给机器人发一条消息，私聊直接发，群聊需要 @机器人。未绑定的聊天会收到机器人在这条消息下的回复：配置了 `BRIDGE_URL` 时是绑定链接，否则提示到管理台完成绑定。打开链接（未登录时先登录），绑定表单已带入应用和聊天，选择机器、工作目录和 Agent 类型（Claude / Codex / Antigravity）后保存；Agent 类型为 Claude 时还要选择权限模式：default（需要确认的操作发卡片到飞书，新建时默认）或 auto（由 Claude 自动决定，很少需要确认）。也可以在「会话绑定」页点击「新建绑定」，从等待绑定的聊天中选择。保存后，这条首条消息随即开启第一个话题。群聊可以选择是否仅 @机器人时触发，私聊总是触发。链接 30 分钟内有效，期间同一聊天的后续消息不会重复回复；过期后再发消息会得到新链接。等待绑定的聊天只保存在内存中，Bridge 重启后需要重新发消息。每个应用下一个聊天只能有一条绑定。绑定列表显示每个 Claude 绑定的权限模式，点击「修改权限模式」可以修改；修改只影响之后新开的话题，已在运行的话题保持启动时的模式。绑定的其他字段不能修改。
4. **话题**：聊天里的一条顶层消息开启一个话题（绑定要求 @机器人 时，这条消息需要 @机器人）。Bridge 在 Herdr 的工作区「飞书 · 绑定名称」中为话题新开一个 tab，在工作目录启动所选 Agent（Claude 使用绑定的权限模式），把消息发给它。工作目录不存在时，Bridge 开 tab 前先在目标机器上创建它；创建失败（例如没有权限）按启动失败处理。话题内的后续消息直接发给同一个 Agent，不需要 @机器人。Bridge 收下话题里的每条消息后，立即给这条消息贴上 `OneSecond` 表情，Agent 处理完这条消息的那一轮后取消；消息没有发给 Agent 时（启动失败、Agent 等待确认、发送出错、会话已结束）也会取消。Agent 每轮结束时的最终回复以不带标题的卡片回复到话题里（markdown 渲染，卡片占满宽度），包括在 Herdr 中直接对这个 Agent 说话产生的回复。Agent 首次在某个目录启动时可能停在确认界面（例如 Claude 的目录信任提示），这时 Bridge 会在话题里提示，需要到 Herdr 中处理后重发消息。Agent 退出或换成别的 Agent 后，话题结束，Bridge 在下一次轮询或下一条消息时在话题里提示「该话题的会话已结束，请发起新话题」。
5. **审批与提问**：Claude 或 Codex 在话题里请求权限（执行命令、改文件等）或 Claude 用 AskUserQuestion 提问时，话题里出现一张卡片。权限卡片列出工具名、说明和命令或参数预览，按钮为允许 / 总是允许 / 拒绝（只有 Claude 给出了规则建议时才有「总是允许」，Codex 只有允许 / 拒绝）；提问卡片把每个问题列成单选或多选，另有一个「其他」输入框，填了「其他」就以它为答案，有问题没答时提示且不提交。只有应用允许名单里的人能点，其他人点击会收到提示。点击后卡片改为结果和点击人，例如「已允许 · @张三」，按钮去掉。拒绝时 Claude 中断本轮，之后在话题里发新消息继续；Codex 拒绝这次调用并继续本轮。请求在飞书之外结束时（超时、本轮结束、Agent 退出、Herdr 重启），卡片改为「已失效（超时、已在终端处理或本轮已结束）」。Claude 的终端确认框在此期间照常可用；Codex 的请求最多等 10 分钟，之后卡片失效，终端里显示审批框。Agent 停在飞书回答不了的交互上（Codex 提问、MCP 表单、Claude 的计划确认、Antigravity 的命令审批和 `ask_question`、目录信任确认等）时，话题里提示一次「Agent 正在等待终端里的操作，请到 Herdr 中处理」；Antigravity 不发卡片，它的审批和提问都要到终端处理。

   审批和提问是否等待飞书的回答，由 Herdr 中这个 pane 的外部回答设置决定（见下面「实现」），不再由环境变量决定。需要支持 `herdr pane remote-answers` 的 Herdr，并在每台运行 Agent 的机器上重装集成（`herdr integration install claude` / `codex`）：旧版 hook 只在有 `HERDR_REMOTE_ANSWERS` 环境变量时等待答案，而 Bridge 已不再注入这个变量，不重装的话卡片不会出现。已经在运行的 Agent 是否加载新 hook 取决于 Agent 自己（Claude Code 会重新读取 settings 里的 hook，Codex 需要重启）。从注入环境变量的旧版 Bridge 升级后，之前开的话题的 Agent 没有打开这个设置，Bridge 第一次轮询时就会结束这些话题；这些 Agent 仍在原来的 tab 里运行，需要的话用 `/接管` 重新接上。
6. **接管正在运行的 Agent**：在任意已绑定的聊天里发一条只有 `/接管` 的根消息（绑定要求 @机器人 时需要 @机器人），机器人在这条消息的话题里回一张卡片：一个下拉框列出 Bridge 已连接的所有机器上正在运行的 Agent，不受这个绑定的机器限制，每项写作「机器 · 名称 · 类型 · 状态」，例如「cpu2 · 赤尾重构 · Claude · 空闲」，下面是「接管」按钮。名称是用户在 Herdr 里起的名字：pane 的名称，没有时用 tab 的名称（Herdr 给没命名的 tab 显示的序号不算），再没有时用 workspace 的名称，都没有时才用 pane ID；同一台机器上可选的 Agent 名称相同时，名称后面加上 pane ID 区分。已经关联到话题的 pane（任意绑定，包括正在启动的话题）不列出；读取失败的机器在下拉框下面显示「机器 · 连接失败」；已断开桥接的机器不列出。选好后点「接管」，Bridge 再读一次那台机器的状态，确认这个 pane 里仍是卡片上的那个 Agent、也没有被别的话题关联，然后打开这个 pane 的外部回答设置，把这个话题关联到它（话题标题为「接管 · 名称」），在话题里发一条说明（机器、类型和名称、工作目录），有回复时接着发最近一条回复的全文，并把卡片改为「已接管 · @点击人」，之后卡片不再接受选择。没选就点「接管」时提示先选择并重画卡片；Agent 已退出或已变化、设置打不开、或者已被别的话题接管时，不关联，卡片改为原因和最新的列表，可以重新选择。选择之前，话题里的消息只会收到「请先在上面的卡片中选择要接管的 Agent」，管理台里这个话题显示为「待选择」。

   接管后的话题和 Bridge 新开的话题一样：话题里的消息发给这个 Agent，回复转回话题（包括在终端里直接对它说话产生的回复），审批和提问发卡片，飞书回答不了的阻塞发提示，表情随一轮结束而取消；说明里已经发过的那条回复不会再转发。话题里发 `/结束接管`，Bridge 关闭这个 pane 的外部回答设置并结束话题，在话题里说明 Agent 仍在终端的 pane 里运行，之后话题里的消息不再发给它；设置关不掉时话题保持关联并提示稍后重试（Agent 已经不在时直接结束）。pane 关闭、Agent 退出或换成别的 Agent 时，话题同样结束，并提示「被接管的 Agent 已退出、已更换或所在 pane 已关闭，话题已结束接管」。

   接管不重启 Agent，也不移动 pane：pane 留在原来的 workspace 和 tab 里，不进入绑定的工作区，正在进行的一轮不受影响，终端里照常可以继续使用；Bridge 不会关闭、重启或移动被接管的 pane。用户在终端里输入的内容不会同步到飞书。没有向 Herdr 上报会话的 Agent（例如手动启动、连着后台 app-server 的 Codex）的回复可能无法转回飞书，说明里会提示；这是 Herdr 对 Codex 的既有限制。`/接管` 只在根消息上识别，`/结束接管` 只在接管来的话题里识别，其他位置的同名文字照常作为消息发给 Agent；这两条命令本身不贴表情。卡片只有应用允许名单里的人能点。一个 pane 同时最多关联一个话题。

手动添加飞书应用时，需要配置机器人收发消息的权限、发送和删除消息表情回复的权限（`im:message.reactions:write_only`），以及消息事件 `im.message.receive_v1`，通过长连接接收事件；审批与提问卡片还需要订阅卡片回调 `card.action.trigger`（在开放平台「事件与回调」的回调配置中选择长连接接收），然后发布应用。发送和更新卡片使用发消息的权限（`im:message:send_as_bot`），不需要另加权限。官方接入流程已订阅卡片回调。

## 实现

- Node.js ES Modules 后端；管理台为 React + Vite（`web/`），构建产物为同源 JS/CSS，满足服务端 CSP（不允许内联脚本、内联样式与外部资源）。
- `@larksuite/channel` 负责应用注册、连接、消息规范化和话题内回复；各应用使用独立 Channel 和缓存。
- 连接成功和验证凭证后，Bridge 通过 `/open-apis/bot/v3/info` 读取机器人名称、open_id 和头像地址。头像只接受 https、1 MB 以内、类型为 `image/png`、`image/jpeg`、`image/gif` 或 `image/webp` 的响应（不接受 SVG，因为 SVG 可以携带脚本，而头像与控制台同源），保存在状态目录的 `avatars/` 下，由需要登录的 `/api/apps/avatar` 提供；下载失败只记录日志，保留旧头像，不影响连接。删除应用时一并删除头像。
- Bridge 在目标机器上只运行 Herdr CLI 和 `mkdir`：`agent list`、`pane list` 读取机器上的终端与 Agent；`workspace list/create`、`tab create`、`agent start`、`agent prompt` 为话题开 tab、启动 Agent 并发送消息，Claude 绑定的 `agent start` 末尾带 `-- --permission-mode <default|auto>`，由 Herdr 传给 Claude；Codex 绑定的 `agent start` 末尾带 `-- --no-daemon`，让 Codex 在话题 pane 里运行，而不是连到共享的后台服务（后台服务里的 hook 带的是启动它的那个 pane 的 Herdr 环境变量，session、回复和审批都会报到错误的 pane）；Antigravity 绑定的 `agent start` 不带额外参数，末尾也没有 `--`；`agent replies` 取回 Agent 的回复；`agent requests`、`agent answer` 读取并回答 Agent 等待中的审批和提问；`pane remote-answers <pane> on|off` 打开和关闭 pane 的外部回答设置（Bridge 只看命令成功与否）。Herdr 遇到不存在的 `--cwd` 会退回 home 目录，所以每次为话题开 tab 前（包括在已有工作区中开 tab）先执行 `mkdir -p -- <工作目录>`；保存绑定时不创建目录。工作目录中的 `~/` 在目标机器上展开。
- 消息表情：Bridge 收下消息后立即贴 `OneSecond` 表情，不在话题队列里排队，并在话题上记录表情 ID。`agent prompt` 成功后记下返回的 Agent `state_change_seq`（Agent 状态每变化一次就增加）；之后某次轮询中，同一 Agent 为 `idle` 或 `done` 且 `state_change_seq` 大于记下的值时，这一轮结束，取消表情，排在同一话题队列里，同一次轮询有新回复时先发回复。消息没有发给 Agent 时立即取消这条消息的表情；投递前发现 Agent 已不存在、话题结束时，取消该话题全部表情。贴表情失败只记录日志，消息照常投递；取消失败只记录日志，记录照样删除，不重试。
- 回复转发：机器每次轮询（5 秒）拿到 `agent list` 后，对该机器上 `ready` 的话题按 pane 找到它关联的 Agent（见下面的话题存活）；Agent 的 `reply_seq`（最新一条回复的序号）与话题记录的序号不同时，用 `agent replies <pane> --after <序号>` 取回新回复，按序号顺序在话题内回复。每条回复是不带标题的卡片（JSON 2.0）：正文放在 markdown 组件里，卡片占满宽度（`width_mode: fill`，回复里常有代码和表格），摘要（`config.summary`，会话列表和推送通知里显示，Bridge 发的每张不带标题的卡片都有）取正文开头，空白折叠成一个空格，最多 100 个字符。飞书拒绝请求体超过 30 KB 的卡片消息，而卡片 JSON 在请求体里还要作为字符串再序列化一次（引号和反斜杠各占 4 字节，中文字符 3 字节），所以 Bridge 按两次序列化后的 UTF-8 字节数计算，每张卡片在请求体里不超过 28000 字节。放不进一张卡片的回复（Herdr 每条最多保留 64 KiB）拆成多张卡片按顺序发出：在行尾拆分；代码块被拆开时，前一张卡片末尾闭合它，后一张开头用同一个围栏行（含语言标记）重新打开；单独一行就放不下时按字符拆开。被 Herdr 截断的回复在最后一张卡片的正文之后以纯文本提示到 Herdr 查看完整内容。一条回复的某张卡片发送失败时，这条回复后面的卡片不再发送（不在中间留下缺口），日志记录已经发出几张；序号在发送前已经落盘，不会重发。取回与发送和同一话题的消息投递排在同一队列里。Herdr 重启或 handoff 后序号从 1 重新计数，这时取回全部保留的回复，只发送序号不超过 `reply_seq` 的部分。回复由 Agent 的 Stop hook 上报给 Herdr，需要支持 `agent replies` 的 Herdr（本仓库的 fork 版本），并重装集成（`herdr integration install claude` / `codex` / `antigravity-cli`）；旧版 Herdr 的 Agent 没有 `reply_seq`，Bridge 不转发。Antigravity 的回复由 antigravity-cli 集成的 Stop hook 上报，需要装上带 Stop 回复上报的集成（`herdr integration install antigravity-cli`）；旧版集成只上报会话 ID，agy 话题收不到回复。重装集成后，已经在运行的 agy 要重新启动才会加载新的 hook。Herdr 每个 Agent 只保留最近 8 条回复，两次轮询之间更早的回复会丢失。
- 权限模式：Claude 在 auto 模式下由分类器直接放行或拒绝大多数操作，仍然弹出的确认框（例如读工作目录外的文件）带 `personOnly` 标记，不交给 `PermissionRequest` hook，所以话题里几乎不出现审批卡片；有的机器上 Claude Code 默认就是 auto（例如 2.1.285），所以 Bridge 启动 Claude 时总是明确传入绑定的权限模式。绑定只支持 default 和 auto，没有这个字段的旧 Claude 绑定按 default 处理。修改权限模式的接口 `POST /api/bindings/permission-mode`（`{id, permissionMode}`）只改这一个字段，只接受 Claude 绑定，不影响已经在运行的 Agent。
- 审批与提问卡片：Claude 和 Codex 的 `PermissionRequest` hook 总是把请求交给 Herdr；pane 当前的 Agent 打开了外部回答设置时 Herdr 让 hook 等待答案，否则立即结束请求，终端照常弹出确认框。Bridge 为新开的话题在 `agent start` 之后（包括 `agent_not_ready`）、话题就绪之前执行 `pane remote-answers <pane> on`，打开失败按启动失败处理；接管时同样先打开再关联。这个设置属于 pane 当前的 Agent，Agent 退出、被释放或换成别的 Agent 时 Herdr 自动清除，live handoff 后保留。Antigravity 没有能等待答案的审批 hook，这个设置对它不起作用：它的命令审批和 `ask_question` 由 Herdr 的屏幕检测报为 `blocked`，话题里只出现下面的阻塞提示。需要支持 `agent requests` 的 Herdr（本仓库的 fork 版本）并重装集成；旧版 Herdr 的 Agent 没有 `request_ids`，Bridge 不发卡片。
  - 发现：每次轮询时，`ready` 话题的 Agent 的 `request_ids` 与话题记录的卡片不一致，就在话题队列里处理：`agent requests <pane>` 取回请求，给这次 `request_ids` 里还没有卡片的请求在话题内发卡片（JSON 2.0 卡片），成功后记下请求 ID、卡片消息 ID 和卡片标题；记录里有、`request_ids` 里已经没有的请求，卡片改为「已失效」并删除记录。卡片至少发送一次：发送失败只记录日志，下一次轮询重试，所以网络异常时可能出现重复卡片。Bridge 重启后，第一次轮询给还没有卡片记录的请求补发卡片。
  - 点击：卡片点击走 Channel 独立的卡片队列（`chatQueue.cardActions: 'separate'`），也不排在话题队列里，所以不会被同一聊天、同一话题里的消息处理挡住。不在应用允许名单里的人点击时只收到提示。允许的点击立即以提示回应飞书（飞书只等几秒），然后在后台用 `agent requests` 确认请求还在、内容与卡片一致，再调用 `agent answer <pane> <请求 ID> --decision allow|allow_always|deny`（拒绝时带 `--message 用户在飞书中拒绝了这次操作`）或 `--answers <问题文本 → 答案列表的 JSON>`，完成后把卡片改为结果。请求已不存在或 Herdr 报 `request_not_found` 时卡片改为「已失效」；其他失败时卡片改为「提交失败」并删除记录，Agent 仍在等待时下一次轮询发一张新卡片。正在由飞书回答的请求不会被轮询改成「已失效」，同一张卡片的第二次点击等第一次处理完。卡片只记标题，所以「已失效」的卡片只显示标题。
  - Channel 会丢弃同一张卡片上同一个人、同一按钮值的重复点击（12 小时内），所以提问没答全时 Bridge 重画这张卡片（保留已选的答案），每次画卡片时按钮值带新的编号，才能再次提交。卡片按钮值里带请求内容的摘要：Herdr 重启或 handoff 后请求 ID 从 1 重新计数，点击时摘要不一致就按「已失效」处理，不会回答到另一个请求上。
  - 阻塞提示：Agent 为 `blocked`、没有等待中的请求，并且连续两次轮询的 `state_change_seq` 相同时，在话题里提示一次「Agent 正在等待终端里的操作，请到 Herdr 中处理」。同一次阻塞（同一个 `state_change_seq`）只提示一次；发消息时已经因为 `agent_blocked` 提示过的，Bridge 再读一次 `agent list` 记下这次阻塞，不再重复。
- 话题存活：`ready` 的话题（新开的和接管来的一样）只在话题机器的 `agent list` 里，它的 pane 上的 Agent 报告 `remote_answers: true` 时算作还关联着这个 Agent，与 Agent 名称和会话无关。Herdr 在 Agent 退出、被释放或换成别的 Agent 时清除这个设置，所以它同时回答了「pane 还在吗」和「还是不是那个 Agent」。接管来的 Agent 名称不由 Bridge 决定，而会话 ID 会在 `/clear` 之类的操作后变化，也可能根本没有（连着后台 app-server 的 Codex），按名称或会话都认不准。另一个好处是话题不会处在「还关联着、但审批卡片已经失效」的状态。发消息前读一次 `agent list`，Agent 不再关联时结束话题并提示；轮询拿到的列表里没有关联的 Agent 时，在话题队列里再读一次 `agent list` 确认后才结束，因为这份列表可能是在话题打开设置之前读的。新开话题和接管都在话题变成 `ready` 之前打开设置。
- 接管：`/接管` 的话题记录在发卡片之前创建（状态 `choosing`，消息 ID 落盘去重），卡片的消息 ID 记在 `adopted.picker`。卡片内容来自每台启用机器的一次 `api snapshot`：它在同一时刻给出 `agent list` 的全部条目，以及 pane、tab 和 workspace 的列表，名称就从这三者的 `label` 里取（`agent list` 的条目不带 pane 的名称），每台机器只调用一次 Herdr；只列有 Agent 类型的条目。卡片是一个表单：下拉框（`select_static`）的每个选项的值是一段 JSON，带机器、pane、Agent 类型，以及卡片上看到的 Herdr 名称和会话 ID；「接管」按钮提交表单，按钮值只标明这是接管卡片和这次画卡片的编号。提交时用那台机器新的 `api snapshot` 核对这几项，并检查 pane 没有被话题占用（正在启动或已就绪的话题，以及正在进行中的另一次接管，后者只记在内存里）；没有选项或选项值无效时按没选处理。核对通过后依次执行 `pane remote-answers <pane> on`、取回最近一条回复、把话题记为 `ready`（机器、workspace、tab、pane 取自所选 Agent，`replySeq` 为说明里那条回复的序号，`adopted` 加上 Agent 类型和会话 ID），再发说明和更新卡片。选中在话题队列里处理，和话题里的消息排在一起。卡片点击和请求卡片一样走 Channel 的独立卡片队列并立即回应提示；每次画卡片按钮值带新的编号，因为 Channel 按卡片、点击人和按钮值去重，不看表单里选了什么，所以没选就提交时也要重画卡片，下一次提交才不会被当成重复丢掉。`/结束接管` 执行 `pane remote-answers <pane> off`，成功后结束话题；失败时再读一次 `agent list`，Agent 已不关联就按 Agent 消失结束，否则提示稍后重试。
- Bridge 校验允许名单和聊天路由。未绑定聊天的待绑定记录以 128 位随机 token 标识，只保存在内存中；保存绑定时应用和聊天只取自 token 对应的记录，不接受浏览器传入。首条消息只用于绑定后开启第一个话题，不写入状态目录，也不返回浏览器。
- 消息至多发送一次：消息 ID 在调用 Herdr 之前落盘，重复到达的消息直接忽略；同一话题内的消息按顺序发送，发送失败只记录日志，不重试。回复同样至多转发一次：每条回复的序号在发送前落盘，发送失败只记录日志，不重试。
- 状态目录保存机器、应用、绑定、话题、连接日志和机器人头像。话题只保存首条消息的前 24 个字符作为标题、最近 50 个消息 ID 用于去重、已转发回复的最新序号，尚未取消的表情（消息 ID、表情 ID 和发送时的 `state_change_seq`）、等待中请求的卡片（请求 ID、卡片消息 ID 和卡片标题，例如「权限确认 · Bash」），已提示过的阻塞的 `state_change_seq`，以及接管来的话题的 `adopted`（卡片消息 ID、接管的 Agent 类型和会话 ID），不保存其他消息内容、回复内容和请求内容；日志不记录回复内容和请求内容。消息 ID、表情记录和卡片记录不返回浏览器。
- 管理接口要求登录，校验 Host/Origin；应用 Secret 不回传浏览器。关闭或重启 Bridge 不会停止 Herdr 与其中的 Agent。

当前支持文本及不带资源的富文本消息。Bridge 在飞书里发的消息都是卡片：自己的状态（未绑定聊天的绑定提示、启动失败、会话已结束、Agent 等待确认或等待终端操作、接管的说明和结束）是不带标题的纯文本卡片，绑定提示里的链接可以点击；Agent 每轮的最终回复是不带标题的 markdown 卡片；另有带标题的审批、提问和接管卡片；处理中的消息以表情标记；不转发中间过程和其他工具调用。解除绑定会删除它的话题记录，并关闭其中已就绪话题的 pane 的外部回答设置，但不会关闭 Herdr 中的 tab 或 pane。自动关闭 tab、文件输入、流式输出和独立手机客户端尚未实现。

审批与提问的限制：Codex 的 `request_user_input`、MCP 表单、Claude 的计划确认（ExitPlanMode），以及 Antigravity 的全部命令审批和 `ask_question`，只提示到 Herdr 处理，不能在飞书回答；不用模拟按键回答任何交互；不能在话题里用普通消息回答提问；Codex 没有「总是允许」。Bridge 不识别「终端先回答了」：Claude 在终端先回答后，卡片保持可点，直到本轮结束才失效，期间点击不会生效（Claude 丢弃迟到的答案），但卡片会显示点击结果。Herdr 不持久化请求，重启或 live handoff 后等待中的请求全部失效，hook 退回终端。Bridge 仍以 5 秒一次的轮询发现请求，不订阅 Herdr 事件。Windows 上的 hook 不上报请求。
